# 自定义菜单进入普通用户边栏设置

## 目标

管理员配置的外部平台菜单包含名称、可选描述、地址和所属区域。如果归属聊天、控制台或个人中心区域，普通用户可以在个人设置的“边栏设置”中单独控制其显示状态；设置卡片展示名称和描述，不展示源地址。归属顶栏或管理员区域的菜单不进入普通用户设置。

## 现状问题

- 管理员配置已经保存 `custom` 菜单，并能按区域渲染到侧边栏。
- 普通用户设置页只渲染固定模块，没有把管理员配置的 `custom` 菜单转换成设置项。
- `useSidebar` 的最终用户配置忽略 `custom`，因此用户无法关闭自定义菜单；导航也不会读取用户对自定义菜单的偏好。

## 设计

### 数据结构

沿用现有用户 `sidebar_modules` JSON，在顶层增加可选的 `custom` 对象：

```json
{
  "console": { "enabled": true, "log": true },
  "custom": {
    "custom-123": true
  }
}
```

键使用管理员配置中的菜单 `id`，值为布尔值。未写入的菜单默认显示，保证已有用户和管理员新建菜单兼容；管理员禁用、删除或配置无效的菜单不会显示。

### 菜单归属与权限

- `chat`、`console`、`personal`：显示在对应用户边栏设置区域，用户可独立开关。
- `topbar`、`admin`：不显示在普通用户边栏设置中，也不受普通用户 `custom` 开关影响。
- 管理员的 `enabled` 和 URL 校验优先于用户设置。

### 前端行为

- `useSidebar` 暴露用户自定义菜单可见性判断，并将用户 `custom` 偏好纳入最终配置。
- `SiderBar` 在构建自定义菜单时过滤用户关闭的菜单。
- `NotificationSettings` 根据管理员菜单的 `placement` 动态追加自定义设置卡片，复用固定模块的卡片和开关样式。
- 新菜单对没有历史 `custom` 配置的用户默认开启；保存后只写入用户明确的开关状态。

## 验收标准

1. 管理员新增一个归属控制台的菜单并保存后，普通用户个人设置的边栏设置中出现该菜单。
2. 普通用户关闭该菜单并保存后，侧边栏中的菜单消失；重新打开后恢复。
3. 菜单归属聊天或个人中心时，设置卡片出现在对应区域。
4. 菜单归属顶栏或管理员区域时，普通用户设置中不出现，原有渲染逻辑不变。
5. 已有用户没有 `custom` 字段时，管理员启用的聊天、控制台、个人中心菜单仍然显示。
6. 删除或禁用管理员菜单后，普通用户不能通过旧的用户配置重新显示它。

## 验证

- 添加 `useSidebar` 纯函数测试，覆盖默认显示、用户关闭、顶栏/管理员排除和管理员禁用。
- 运行前端相关测试、ESLint、Prettier、构建和 `git diff --check`。
