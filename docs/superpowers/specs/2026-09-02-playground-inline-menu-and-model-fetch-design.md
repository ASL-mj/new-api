# NewAPI Fork 本轮功能设计

## 范围

本轮只实施以下七项已确认需求，不改生产环境，不启动本地服务，不重复实现此前已经完成的监控、额度、多密钥和使用日志功能：

1. 操练场按分组筛选模型。
2. 映射模型的展示名称与上游实际请求值分离。
3. 操练场支持推理强度选择，并让配置和使用日志可追溯。
4. 外部平台内联菜单支持 Lucide 图标配置和站内内联打开。
5. 用户列表额度排序统一按总额度，保留邀请人数排序，均支持三态排序。
6. README 补充 Fork 的完整功能、配置、启动方式、截图和限制说明。
7. 获取上游模型时统一处理 Base URL 末尾斜杠。

## 设计决策

### 1. 操练场模型筛选

为 `/api/user/models` 增加可选 `group` 查询参数。未传参数时保持原有返回格式和权限逻辑，避免影响令牌页面及其他调用方。操练场加载分组后，按当前分组重新请求模型；`auto` 分组沿用现有自动分组并集逻辑。

分组切换时，如果当前已选模型不属于新分组，立即清空该模型并提示用户重新选择。模型选项内部统一使用 `{ label, value }`，兼容后端现有字符串数组；页面展示 `label`，请求 payload 使用 `value`。

### 2. 映射模型

前端不根据模型映射猜测渠道上游名称。模型选项的 `value` 必须是客户端请求值，`label` 只负责显示。后端继续通过现有 `ModelMappedHelper`、`OriginModelName` 和 `UpstreamModelName` 在选定渠道后完成渠道级映射，保证实际发送给上游的是原始请求值或后端解析出的上游值，而不是展示文本。

### 3. 推理强度

操练场参数面板增加“系统默认、none、low、medium、high、xhigh”选项。选择“系统默认”时不发送字段，由系统和上游决定；选择具体值时发送 `reasoning_effort`。该设置进入 localStorage、导入导出、预览请求、实际请求和编辑重发链路。后端继续复用现有请求 DTO、`RelayInfo.ReasoningEffort` 和使用日志 `Other.reasoning_effort`，不新增数据库字段。

### 4. 外部平台菜单图标与内联打开

在现有菜单结构中增加可选 `icon` 字段，保存预置 Lucide 图标名称，不上传单独图标文件。管理员配置页提供有限的图标选择和预览；旧配置或非法名称统一回退 `ExternalLink`。顶栏、聊天、控制台、个人和管理员区域都从同一菜单对象读取图标和 `openMode`。

侧边栏区域使用站内右侧内联网页容器打开外部 URL，不覆盖整个页面；现有管理员可见性、普通用户显示开关和描述字段继续生效。普通用户只控制显示，不修改菜单配置。管理员菜单的 `enabled`、URL 校验和权限优先于用户配置。

### 5. 用户列表排序

移除“剩余额度”排序入口，将额度列排序参数改为 `total_quota`。后端按 `quota + used_quota` 排序，并用用户 ID作为稳定次排序；搜索、筛选和分页都在后端完整结果集上执行。邀请人数继续使用 `aff_count`。两个字段均保持升序、降序、不排序三态，不排序时恢复系统默认排序。

### 6. README

保留上游 NewAPI、QuantumNous、许可证和作者等受保护信息，在 README 增加 Fork 专属章节。按功能模块记录本 Fork 的所有已完成更新，包含用途、入口、配置、接口/字段变化、启动步骤、现有截图资源和已知限制。没有真实采集到的运行截图时不伪造截图，明确说明截图边界。

### 7. Base URL 模型端点拼接

增加统一的安全拼接函数，仅在获取模型的链路使用：先 `TrimSpace`，再移除 Base URL 末尾连续 `/`，确保 endpoint 只有一个前导 `/`。该函数只处理 Base URL 与 endpoint 的连接处，不触碰 `https://`、内部路径或用户保存的原始 Base URL。

覆盖即时获取模型、后台自动同步、特殊渠道模型端点、Gemini `/v1beta/models`、Ollama `/api/tags` 以及倍率同步中独立的模型请求。特殊渠道映射查找同时兼容原始值和去尾斜杠后的规范值，避免用户填写 `https://host/` 时丢失特殊渠道逻辑。

空 Base URL 仍沿用现有默认地址逻辑；实际 Relay 请求转发链路不在本项修改范围内。

## 错误处理与兼容性

- 不改变 `/api/user/models` 未带分组参数时的响应结构。
- 不把展示名称写入实际模型请求。
- 未配置推理强度时省略字段，不强行覆盖上游默认值。
- 旧外部菜单缺少图标时使用 `ExternalLink`。
- URL 拼接失败仍由现有请求错误返回机制处理，并保留上游错误信息。
- 所有数据库访问继续通过 GORM，兼容 SQLite、MySQL 和 PostgreSQL。
- Go 业务 JSON 编解码继续使用 `common.Marshal`/`common.Unmarshal`。

## 验证策略

### 后端

- 测试带和不带末尾 `/` 的 Base URL，覆盖多个 `/`、带路径、空值和特殊渠道映射。
- 测试分组参数对旧模型接口响应格式的兼容性。
- 测试总额度排序 SQL 语义和稳定次排序。
- 测试推理强度明确值能够进入请求 DTO，默认值不会被错误发送。

### 前端

- 测试分组切换清理失效模型并提示。
- 测试 `{ label, value }` 的展示/请求分离。
- 测试推理强度保存、导入导出和 payload。
- 测试旧菜单、非法图标和四类侧边栏内联打开。
- 执行 i18n 检查、ESLint、Prettier 检查和生产构建。

### 交付边界

本轮只在 `dev/skye-v0.13.2-performance` 本地分支修改。完成后执行 Go 定向测试、前端检查、构建和 `git diff --check`；不启动前后端、数据库，不修改生产服务。
